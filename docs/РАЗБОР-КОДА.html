1. Почему в адресе есть решётка

Сайт лежит на GitHub Pages. Это обычный статический хостинг: он отдаёт файлы, но не умеет, как сервер, перенаправлять любой адрес на index.html. Если открыть /modules/relativity и нажать F5, GitHub попробует найти такую папку и вернёт 404.

Решение — HashRouter. Всё, что стоит после #, браузер не отправляет на сервер. Сервер всегда получает только index.html, а маршрут разбирает React уже внутри страницы.

Аналогия. Представь одну книгу. Сервер выдаёт тебе книгу целиком, а # — это закладка: «открой страницу 4». Серверу не важно, какая закладка, он всё равно даёт ту же книгу.

Код. src/main.jsx:

import { HashRouter } from 'react-router-dom'

createRoot(document.getElementById('root')).render(
  <StrictMode>
    <HashRouter>
      <App />
    </HashRouter>
  </StrictMode>,
)

Маршруты. src/App.jsx:

<Routes>
  <Route path="/" element={<HomePage />} />
  <Route path="/modules" element={<ModulesPage />} />
  <Route path="/modules/:moduleId" element={<ModulePage />} />
  <Route path="/modules/:moduleId/:lessonId" element={<LessonPage />} />
  <Route path="/teacher" element={<TeacherPage />} />
  <Route path="*" element={<NotFoundPage />} />
</Routes>

:moduleId и :lessonId — это параметры. Если адрес #/modules/relativity/time-dilation, то moduleId будет relativity, а lessonId — time-dilation.

Что сказать: «HashRouter нужен потому, что GitHub Pages не умеет отдавать index.html на любой путь. С решёткой обновление страницы работает всегда».

Если спросят, почему не красивые адреса без решётки: «Можно, но тогда нужен сервер с fallback или отдельная настройка. Для школьного проекта я выбрал надёжность и бесплатный хостинг».

2. Как работает тема и почему она не мигает

Тема хранится в localStorage под ключом alma-theme. Это обычное хранилище в браузере, как маленькая записная книжка. Никакого сервера и аккаунта.

Главная тонкость: тему нужно поставить до первой отрисовки. Если делать это в React, страница успеет показаться белой на долю секунды, а потом станет тёмной. Это называется «мигание». Поэтому в index.html стоит маленький скрипт, который выполняется сразу. 

var saved = localStorage.getItem('alma-theme')
var theme =
  saved === 'light' || saved === 'dark'
    ? saved
    : window.matchMedia('(prefers-color-scheme: dark)').matches
      ? 'dark'
      : 'light'

document.documentElement.dataset.theme = theme

Дальше в CSS есть два набора переменных: обычный и :root[data-theme="light"]. Компоненты используют var(--color-bg) и не знают, какая тема сейчас. Поэтому переключение — это смена одного атрибута, а не перерисовка всего сайта.

Аналогия. Это как выключатель света в комнате. Лампочки и мебель те же, меняется только положение переключателя. И переключатель запоминает, в каком положении ты его оставил.

Что сказать: «Тема ставится inline-скриптом до отрисовки, поэтому нет белой вспышки. Выбор хранится в localStorage. Если localStorage запрещён, сайт работает, просто не запомнит тему».

3. Как запоминается прогресс

Прогресс — это обычный JSON-объект в localStorage. Ключ — moduleId/lessonId, значение — true, если урок пройден. 

{
  "relativity/classical-crisis": true,
  "relativity/reference-frames": true
}

Код. src/lib/progress.js:

const STORAGE_KEY = 'alma-progress'

export function getProgress() {
  try {
    return JSON.parse(localStorage.getItem(STORAGE_KEY)) || {}
  } catch {
    return {}
  }
}

export function isLessonDone(moduleId, lessonId) {
  return Boolean(getProgress()[`${moduleId}/${lessonId}`])
}

export function markLessonDone(moduleId, lessonId) {
  const progress = getProgress()
  progress[`${moduleId}/${lessonId}`] = true
  localStorage.setItem(STORAGE_KEY, JSON.stringify(progress))
}

try / catch нужен на случай, если в localStorage лежит битый JSON или браузер запрещает доступ. Тогда функция вернёт пустой объект, и сайт не упадёт.

Итоговая работа открывается, когда пройдены все уроки: 

const doneLessons = module.lessons.filter((lesson) =>
  isLessonDone(module.id, lesson.id),
)
const unlocked = doneLessons.length === module.lessons.length

Урок считается пройденным, когда ученик проверил все вопросы квиза, а не когда ответил на 100% правильно. Это специально: цель — провести через материал, а не наказать за ошибку. Оценка считается отдельно.

Аналогия. Это список галочек в блокноте. Галочка значит «я это прошёл», а не «я это знаю на пять». Оценка — отдельная строка.

Что сказать: «Прогресс хранится в localStorage, без аккаунтов и персональных данных. Если очистить браузер, прогресс начнётся заново. Это ограничение модели, но для школы это скорее плюс: я ничего не собираю».

4. Как работает квиз

Квиз — это маленькая машина состояний. Сначала он не начат, потом начат, потом ответы выбраны, потом проверены, потом результат. Всё это хранится в трёх переменных:

  • started — квиз начат или нет;
  • selected — какой вариант выбрал ученик в каждом вопросе;
  • checked — какие вопросы уже проверены.

Подсчёт. src/components/Quiz/Quiz.jsx:

const allChecked = questions.every((question) => checked[question.id])
const score = questions.filter(
  (question) =>
    checked[question.id] &&
    selected[question.id] === question.correct,
).length
const ratio = questions.length > 0 ? score / questions.length : 0

score — сколько правильных. ratio — доля правильных от всех. Дальше оценка: 

function gradeFor(ratio) {
  if (ratio >= 0.9) return 5
  if (ratio >= 0.75) return 4
  if (ratio >= 0.6) return 3
  return 2
}

Пороги: 90%, 75%, 60%. Ниже 60% — двойка. Пересдача не ограничена: кнопка «Пройти ещё раз» очищает selected, checked и started.

Как скрывается урок. В CSS есть такой селектор:

.lesson:has(.quiz--started)
  > *:not(.quiz--started):not(.page-title):not(.breadcrumbs) {
  display: none;
}

Пока квиз не начат, класса quiz--started нет. Как только ученик нажал «Начать», класс появляется, и всё содержимое урока кроме заголовка, хлебных крошек и самого квиза исчезает.

Аналогия. Это как закрыть учебник перед ответом. Ты не можешь подсмотреть, но и не обязан отвечать идеально. После проверки учебник открывается снова.

Честно. Это не античит. Любой, кто откроет DevTools, увидит вопросы в коде страницы. Для школьной самопроверки этого достаточно: убирается соблазн, а не создаётся защита уровня экзамена.

Что сказать: «Во время квиза текст урока скрывается через CSS :has. Это режим самопроверки, а не античит. Для настоящей защиты нужен сервер, который выдаёт вопросы и принимает ответы».

5. Как собирается вариант — самое сложное

Это, наверное, главный алгоритм проекта. Разберём по шагам.

5.1. Зачем нужен seed

Если использовать Math.random(), каждый раз будет новый набор заданий. Это удобно, но нельзя повторить. А учителю нужно: распечатал работу, потерял лист, хочет распечатать снова — и получить тот же вариант.

Поэтому используется детерминированный генератор. Ему дают число — seed. Одно и то же число всегда даёт одну и ту же последовательность случайных чисел. Seed печатается внизу листа как «код варианта».

Аналогия. Это как зерно в Minecraft. Одно число задаёт целый мир. Здесь одно число задаёт набор задач.

5.2. Mulberry32

Код. src/teacher/rng.js:

export function makeRng(seed) {
  let state = (seed >>> 0) || 1

  function next() {
    state = (state + 0x6d2b79f5) >>> 0
    let t = state
    t = Math.imul(t ^ (t >>> 15), t | 1)
    t ^= t + Math.imul(t ^ (t >>> 7), t | 61)
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296
  }

  function int(min, max) {
    return min + Math.floor(next() * (max - min + 1))
  }

  function pick(list) {
    return list[int(0, list.length - 1)]
  }

  function shuffle(list) {
    const result = [...list]
    for (let i = result.length - 1; i > 0; i -= 1) {
      const j = int(0, i)
      const temp = result[i]
      result[i] = result[j]
      result[j] = temp
    }
    return result
  }

  return { next, int, pick, shuffle }
}

Что здесь важно понимать, не запоминая формулы:

  • state — внутреннее состояние. Оно меняется при каждом вызове.
  • next() возвращает число от 0 до 1. Это аналог Math.random(), только предсказуемый.
  • int(min, max) превращает дробь в целое в нужном диапазоне.
  • pick(list) выбирает случайный элемент.
  • shuffle(list) перемешивает список.

shuffle — это алгоритм Fisher–Yates. Идём с конца списка и меняем текущий элемент со случайным из начала. Так каждый элемент может оказаться на любом месте, и все варианты равновероятны. Простой обмен «первый с последним» так не работает.

Пример на пальцах: [1, 2, 3]. Берём индекс 2 (тройку), выбираем случайный индекс от 0 до 2. Если выпал 0, меняем тройку и единицу: [3, 2, 1]. Потом берём индекс 1, выбираем от 0 до 1, и так далее.

5.3. Сколько заданий каждого уровня

Учитель выбирает сложность: базовая, смешанная или повышенная. Внутри — доли. Например, смешанная: 50% базовых, 35% повышенных, 15% высоких.

Если просто умножить и округлить, сумма может не совпасть. Для 10 заданий: 5 + 3,5 + 1,5. Целые части дают 9, одно задание «лишнее». Его отдают уровню с самым большим остатком. Здесь остатки 0, 0,5 и 0,5. Одно задание уходит повышенному уровню, получается 5 / 4 / 1. Сумма всегда ровно 10.

Код. src/teacher/buildTest.js:

function quotaFor(count, mix) {
  const rows = Object.entries(mix).map(([level, share]) => ({
    level,
    whole: Math.floor(share * count),
    remainder: share * count - Math.floor(share * count),
  }))

  let left = count - rows.reduce((sum, row) => sum + row.whole, 0)
  const byRemainder = [...rows].sort((a, b) => b.remainder - a.remainder)

  let index = 0
  while (left > 0) {
    byRemainder[index % byRemainder.length].whole += 1
    index += 1
    left -= 1
  }

  return Object.fromEntries(rows.map((row) => [row.level, row.whole]))
}

left — сколько заданий осталось распределить. byRemainder — уровни, отсортированные по остатку. Цикл добавляет по одному, пока left не станет нулём.

5.4. Выбор задач без повторов

Дальше для каждого уровня берётся свой список генераторов. Он перемешивается, и программа идёт по нему. Кандидат принимается, только если:

  • у него ровно три неверных варианта;
  • его текста ещё нет в used.

used — это Set с текстами уже выбранных задач. Set не хранит повторы, поэтому проверка простая: !used.has(candidate.text).

Код, основная часть:

let pool = topic.generators.filter((generator) => generator.level === level)
let order = rng.shuffle(pool)
let cursor = 0

for (let i = 0; i < need; i += 1) {
  let draft = null

  for (let attempt = 0; attempt < 40; attempt += 1) {
    if (cursor >= order.length) {
      cursor = 0
      order = rng.shuffle(pool)
    }

    const generator = order[cursor]
    cursor += 1
    const candidate = generator.build(rng)

    if (
      candidate &&
      candidate.distractors.length === 3 &&
      !used.has(candidate.text)
    ) {
      draft = candidate
      break
    }
  }

  if (!draft) return

  used.add(draft.text)
  const options = rng.shuffle([draft.correct, ...draft.distractors])

  items.push({
    level,
    points: LEVELS[level].points,
    text: draft.text,
    options,
    correctIndex: options.indexOf(draft.correct),
    explanation: draft.explanation,
  })
}

Число 40 — это защита от бесконечного цикла. Если генератор по какой-то причине не может выдать уникальную задачу, программа не зависнет, а просто оставит это место пустым. Потом сработает запасной добор.

Запасной добор. Если заданий всё равно меньше нужного, программа добирает из всех генераторов подряд, но не больше 500 попыток:

if (items.length < count) {
  let guard = 0

  while (items.length < count && guard < 500) {
    guard += 1
    const generator = rng.pick(topic.generators)
    const candidate = generator.build(rng)

    if (!candidate || candidate.distractors.length !== 3 || used.has(candidate.text)) {
      continue
    }

    used.add(candidate.text)
    // ...добавляем задание
  }
}

В конце задания сортируются по уровню: сначала базовые, потом повышенные, потом высокие. Внутри уровня порядок случайный. Так лист идёт от простого к сложному.

5.5. Баллы

Каждый уровень весит по-разному: базовый — 1 балл, повышенный — 2, высокий — 3. Поэтому оценка считается не по количеству заданий, а по сумме баллов. Об этом следующий раздел.

Что сказать: «Вариант собирается детерминированным генератором. Seed — это код варианта, он печатается на листе. Один и тот же seed даёт тот же набор. Сначала считаются квоты по уровням, потом выбираются задачи без повторов, в конце всё сортируется от простого к сложному».

Если спросят, почему 40 и 500: «Это ограничители, чтобы программа не ушла в бесконечный цикл, если генератор не может выдать уникальную задачу».

6. Откуда берутся неверные ответы

В тесте не должно быть вариантов «42», «—7» и «всё перечисленное». Неверные ответы должны быть похожи на реальные ошибки ученика.

Правильный ответ считается формулой. Потом к нему добавляются типичные ошибки: умножил вместо деления, забыл разделить, перепутал единицы. Всё это фильтруется: вариант должен быть положительным и не совпадать с правильным.

Код. src/teacher/topics/helpers.js:

export function numericAnswer(value, unit, extraValues = []) {
  const suffix = unit ? ` ${unit}` : ''
  const correct = `${formatNumber(value)}${suffix}`
  const seen = new Set([formatNumber(value)])
  const distractors = []

  function tryAdd(raw) {
    if (distractors.length >= 3) return
    if (!Number.isFinite(raw) || raw <= 0) return

    const text = formatNumber(raw)
    if (seen.has(text)) return

    seen.add(text)
    distractors.push(`${text}${suffix}`)
  }

  const candidates = [...extraValues, value * 2, value / 2, value * 3, value / 4]
  candidates.forEach(tryAdd)

  return { correct, distractors }
}

Пример. Скорость 12 м/с, время 5 с, путь 60 м. Правильный ответ — 12. Кандидаты в неверные: 24, 6, 36, 3. Первые три уникальные и положительные, они и попадут в вариант. Получится 12, 24, 6, 36. Все похожи на числа, которые может получить ученик, если ошибётся в операции.

formatNumber делает числа по-русски: запятая вместо точки, неразрывный пробел между тысячами. Поэтому в листе будет 12,5, а не 12.5.

Честно. Алгоритм проверяет формат и вычисление, но не проверяет, что задача методически идеальна для конкретного класса. Поэтому в учительской есть предупреждения, а ИИ-задания обязательно проверяет человек.

Что сказать: «Правильный ответ считается формулой, а не хранится в тексте. Неверные варианты — типичные ошибки: удвоение, деление, забытые единицы. Они фильтруются на уникальность и положительность».

7. Как считается оценка в работе учителя

Здесь шкала другая, чем у ученика. Задания разного уровня весят по-разному, поэтому считать «процент правильных» неправильно. Считаем сумму баллов.

Код. src/teacher/buildTest.js:

export function gradeScale(totalPoints) {
  return {
    five: Math.ceil(totalPoints * 0.85),
    four: Math.ceil(totalPoints * 0.7),
    three: Math.ceil(totalPoints * 0.5),
  }
}

Math.ceil округляет вверх. Если максимум 17 баллов:

  • «5» — с 15 (17 × 0,85 = 14,45, округляем вверх);
  • «4» — с 12 (17 × 0,7 = 11,9);
  • «3» — с 9 (17 × 0,5 = 8,5).

У ученика пороги другие: 90 / 75 / 60 процентов. Это не ошибка. У ученика все вопросы равны, поэтому можно считать долю. У учителя задания весят по-разному, поэтому считаем баллы.

Что сказать: «Оценка в учительской работе считается по сумме баллов, потому что задания разного уровня. Пороги — 85, 70 и 50 процентов от максимума. У ученической итоговой работы другая шкала, потому что там все вопросы равны».

8. Как лист становится страницей A4

Лист — это обычный <article> шириной 210 мм и минимальной высотой 297 мм. На экране он выглядит как бумага. При печати CSS убирает тени и говорит браузеру, что это A4. 

.sheet {
  width: 210mm;
  min-height: 297mm;
  padding: 15mm 14mm;
  background: #ffffff;
  color: #14171a;
}

@media print {
  @page {
    size: A4;
    margin: 0;
  }

  .no-print {
    display: none !important;
  }

  .sheet {
    page-break-after: always;
  }

  .sheet-tasks > li {
    page-break-inside: avoid;
  }
}

Что делает каждая строка:

  • @page { size: A4 } — формат страницы.
  • .no-print — скрывает кнопки и навигацию на бумаге.
  • page-break-after: always — каждый вариант и ключ с новой страницы.
  • page-break-inside: avoid — задание не разрывается между страницами.

Ключ — отдельный лист. Поэтому ученикам можно печатать только страницы с вариантами, а ключ оставить учителю. Это делается выбором диапазона страниц в диалоге печати.

PDF отдельно генерировать не нужно. Браузер сам умеет «Печать → Сохранить как PDF». Поэтому в проекте нет библиотеки для PDF и нет сервера, который что-то рендерит.

Что сказать: «Лист A4 — это HTML с размерами в миллиметрах и print-стилями. PDF получается через системную печать браузера. Ключ печатается отдельно, чтобы его не видели ученики».

9. Как собирается презентация .pptx

Презентация собирается на устройстве учителя через библиотеку pptxgenjs. Это не картинки слайдов, а настоящие текстовые блоки и фигуры. Их можно открыть в PowerPoint, Keynote или «Р7-Офис» и редактировать. 

export async function downloadPresentation({ meta, slides }) {
  const module = await import('pptxgenjs')
  const PptxGenJS = module.default

  const pptx = new PptxGenJS()
  pptx.layout = 'LAYOUT_WIDE'
  pptx.author = 'Alma'

  slides.forEach((item, index) => {
    const slide =
      index === 0
        ? addTitleSlide(pptx, meta, item)
        : addContentSlide(pptx, meta, item, index + 1, slides.length)

    if (item.note) slide.addNotes(item.note)
  })

  await pptx.writeFile({ fileName: `${fileBaseName(meta)}.pptx` })
}

import('pptxgenjs') — динамический импорт. Библиотека тяжёлая, поэтому она загружается только в момент экспорта, а не при открытии сайта. В сборке она вынесена в отдельный файл.

LAYOUT_WIDE — формат 16:9, 13,333 × 7,5 дюйма. Первый слайд титульный, остальные — заголовок, акцентная линия, список пунктов и номер. Заметки докладчика добавляются в заметки слайда, а не на экран.

Как это связано с ИИ. Слайды приходят из ИИ-черновика, а .pptx собирается прямо в браузере. Экспорт работает и без сети, если массив слайдов уже есть. Генерация черновика описана в главе 10.

Что сказать: «Презентация собирается в браузере через pptxgenjs. Текст и фигуры остаются редактируемыми, потому что я не вставляю скриншоты. Библиотека грузится только при экспорте, поэтому сайт не тормозит».

10. Как устроен ИИ-генератор

Прямой доступ к модели нельзя держать в JavaScript: любой пользователь откроет исходники и увидит его. Поэтому нужен сервер-посредник: браузер обращается к нему, а он уже идёт к модели. В Alma посредник работает на Cloudflare Pages Functions, а модель — Workers AI. Отдельного ключа нет: модель запускается на стороне Cloudflare, поэтому в проекте нечего случайно закоммитить. 

Браузер → POST /api/generate → Cloudflare Pages Function → Workers AI
                │
                ├── CORS: только свои сайты
                ├── проверка входа
                ├── лимит 20 запросов в час с IP
                ├── строгий промпт
                ├── таймаут 65 секунд
                ├── разбор JSON
                └── проверка каждого задания

Почему Cloudflare. Сайт лежит на GitHub Pages, а там нет PHP. Cloudflare Pages Functions — бесплатный серверный код без карты и отдельного хостинга. Workers AI даёт 10 000 Neurons в сутки: этого хватает на несколько десятков черновиков. Основной адрес записан в .env.production.

CORS. Сервер принимает запросы только с адресов из белого списка. Если сайт чужой, вернёт 403. Это не даёт посторонним тратить бесплатный дневной запас через свой сайт. HTTP-адреса домена добавлены временно: пока GitHub Pages не выпустил сертификат, сайт открывается по HTTP.

const ALLOWED_ORIGINS = new Set([
  'https://alma-edu.ru',
  'https://www.alma-edu.ru',
  'http://alma-edu.ru',
  'http://www.alma-edu.ru',
  'https://qqquies.github.io',
  'http://localhost:5173',
  'http://127.0.0.1:5173',
])

if (origin && !ALLOWED_ORIGINS.has(origin)) {
  return json({ error: 'Этот сайт не имеет доступа к генератору.' }, 403, cors)
}

Лимит. С одного IP принимается не больше 20 запросов в час. Счётчик живёт в памяти экземпляра Worker и сбрасывается при перезапуске, поэтому это ограничитель от зацикливания, а не полноценная защита. Главный ограничитель — дневной запас Workers AI.

if (entry.count >= RATE_LIMIT) {
  throw new HttpError(
    429,
    'Слишком много запросов с этого адреса. Подождите немного и попробуйте снова.',
  )
}

Защита от подсказок. Тема приходит от учителя. Модель может попытаться выполнить инструкцию, спрятанную в тексте темы. Поэтому в промпте сказано: тема — это данные, а не команда. Это называется prompt injection, и с ним борются именно так.

Проверка ответа. Сервер принимает только задания, где ровно четыре разных варианта и correctIndex от 0 до 3. Битые задания отбрасываются. Клиент проверяет ещё раз, чтобы в вёрстку не попал мусор.

// Ровно четыре разных варианта — иначе задание не печатаем.
if (options.length !== 4 || new Set(options).size !== 4) continue

let correct = raw.correctIndex

if (typeof correct === 'string' && /^\d+$/.test(correct)) {
  correct = Number(correct)
}

if (!Number.isInteger(correct) || correct < 0 || correct > 3) continue

Если модель сомневается в ответе, она ставит check: "mismatch". В интерфейсе такое задание помечается «проверить ответ». Это не оценка, а сигнал учителю.

Перекрёстная проверка. Сервер смотрит на объяснение: если там написано «Подставляем x = 10», а выбранный вариант — «8», сервер выбирает вариант, совпадающий с объяснением, и всё равно помечает задание check: "mismatch". Объяснение тоже может быть ошибочным, поэтому окончательное решение остаётся учителю. Если модель сама пишет «ответ не является вариантом», задание не печатается.

Статус. ИИ подключён и работает: 5 заданий генерируются примерно за 20–60 секунд, 8 слайдов — за 20–40 секунд. Если модель стоит в очереди, запрос может не уложиться в минуту — тогда Alma честно просит попробовать ещё раз. Если модель вернула обрезанный JSON, сервер делает одну повторную попытку. Модель может ошибиться в арифметике, поэтому черновик всегда проходит экран проверки. На сервере есть белый список сайтов, лимит и проверка формата; для серверной части написаны 16 автотестов. Банк физики, уроки, печать и прогресс по-прежнему работают без ИИ.

Что сказать: «ИИ работает как черновик. Браузер отправляет тему на Cloudflare, сервер вызывает Workers AI и проверяет формат ответа. Отдельного ключа нет. Модель не ставит оценки: учитель проверяет каждое задание и каждый слайд».

11. Как двигаются симуляции

Все три модели используют общий хук useAnimationFrame. Он вызывает функцию на каждом кадре и передаёт время с прошлого кадра в секундах — dt. 

export default function useAnimationFrame(callback, active = true) {
  const callbackRef = useRef(callback)

  useEffect(() => {
    callbackRef.current = callback
  })

  useEffect(() => {
    if (!active) return undefined

    let frameId
    let lastTime = performance.now()

    const loop = (now) => {
      const dt = Math.min((now - lastTime) / 1000, 0.05)
      lastTime = now
      callbackRef.current(dt)
      frameId = requestAnimationFrame(loop)
    }

    frameId = requestAnimationFrame(loop)
    return () => cancelAnimationFrame(frameId)
  }, [active])
}

Зачем ограничение 0.05: если вкладка была свёрнута 10 секунд, без ограничения объект телепортировался бы через весь экран. С ограничением движение продолжится плавно.

active — это пауза. Когда active = false, новый кадр не запрашивается, браузер не тратит ресурсы. cancelAnimationFrame в очистке нужен, чтобы при уходе со страницы цикл остановился.

11.1. Световые часы

В модели два одинаковых прибора. У покоящихся фотон проходит расстояние между зеркалами за HALF_TICK. У движущихся тот же цикл растягивается в gamma раз.

gamma = 1 / sqrt(1 - beta²)
tau = gamma * HALF_TICK

beta — доля скорости света. При 0,6 gamma равна 1,25, при 0,95 — примерно 3,2. Чем быстрее часы, тем реже они «тикают». 

const gamma = 1 / Math.sqrt(1 - beta * beta)
const tau = gamma * HALF_TICK

movPhase.current += dt
if (movPhase.current >= tau) {
  movPhase.current -= tau
  movDir.current *= -1
  movCountRef.current += 1
  setMovCount(movCountRef.current)
}

Счётчики отражений показывают разницу. След фотона — это ломаная: он движется вверх-вниз и одновременно вправо вместе с часами.

Где я упростил. Это визуальная модель, а не решение уравнений Максвелла. Скорость света условна, наклонный путь не считается отдельной траекторией — я задаю растяжение периода через gamma.

11.2. Молнии и поезд

В момент старта бьют две молнии. Свет расходится кругами радиуса r = c · t. Поезд едет вправо, пассажир тоже. 

const passengerX = CENTER_X + v * t
const distRight = Math.abs(RIGHT_X - passengerX)
const distLeft = Math.abs(passengerX - LEFT_X)

if (!flags.passRight && distRight <= radius(t)) {
  flags.passRight = true
  // правая вспышка достигла пассажира
}

Человек на платформе стоит в центре: расстояния до вспышек равны, свет приходит одновременно. Пассажир едет вправо: правая вспышка оказывается ближе, левая — дальше. Поэтому правая достигает его раньше.

Флаги passRight, platBoth, passLeft не дают событию записаться дважды.

Где я упростил. Скорости преувеличены. Настоящий поезд не может ехать со скоростью, сравнимой со светом. Это мысленный эксперимент, а не реальная установка.

11.3. Мяч в поезде

Для наблюдателя на платформе скорость мяча складывается из скорости поезда и скорости мяча внутри вагона:

v_мяча = trainSpeed + ballSpeed
const scaledDt = dt * TIME_ZOOM

frontX.current += trainSpeed * scaledDt

if (ballActive.current) {
  ballX.current += (trainSpeed + ballSpeed) * scaledDt
}

TIME_ZOOM = 4 ускоряет анимацию, но соотношение скоростей сохраняется. Это классическая формула, а не релятивистская. Она нужна, чтобы показать привычную картину, а потом сравнить её со светом.

Что сказать: «Все модели используют общий цикл requestAnimationFrame. dt ограничен 0,05 секунды, чтобы после свёрнутой вкладки объект не прыгал. В световых часах период растягивается через gamma, в молниях события считаются по радиусу света, в мяче — классическое сложение скоростей».

12. Как сайт попадает на домен

Сборка и публикация идут автоматически. При каждом push в main GitHub Actions запускает workflow. 

- name: Install dependencies
  run: npm ci

- name: Build
  run: |
    npm run build -- --base=./
    cp dist/index.html dist/404.html

- name: Upload artifact
  uses: actions/upload-pages-artifact@v3
  with:
    path: dist

npm ci ставит зависимости строго по lock-файлу, поэтому сборка воспроизводима. --base=./ делает ссылки на файлы относительными. Один и тот же билд работает и в подпапке /alma-site/, и в корне домена.

cp dist/index.html dist/404.html — запасной вариант. Если пользователь откроет неизвестный путь, GitHub отдаст 404.html, а там уже работает React Router.

public/CNAME содержит alma-edu.ru. При сборке файл попадает в корень dist, и GitHub Pages понимает, какой домен использовать.

DNS: четыре A-записи домена указывают на IP GitHub Pages, www — CNAME на qqquies.github.io. Домен куплен в Timeweb, но сайт живёт на GitHub Pages. Это разные услуги: домен — адрес, хостинг — место, где лежат файлы.

HTTPS включается в настройках GitHub Pages после подтверждения домена. Если кнопка «Enforce HTTPS» недоступна, обычно нужно подождать, пока DNS подтвердится и выпустится сертификат.

Что сказать: «Сайт собирается в GitHub Actions и публикуется на GitHub Pages. Относительные пути позволяют использовать один билд и на старом адресе, и на домене. Домен куплен в Timeweb, DNS указывает на GitHub. ИИ-часть живёт отдельно, на бесплатном Cloudflare Pages, поэтому PHP-хостинг не нужен».

13. Быстрые ответы на вопросы

Вопрос Ответ
Почему не готовый конструктор тестов? Готовые сервисы требуют подписку и интернет. Мой банк работает офлайн, ответы считаются формулами, а вариант можно воспроизвести по коду.
Как работает ИИ? Браузер отправляет тему на Cloudflare Pages Function. Сервер добавляет промпт, вызывает Workers AI, проверяет формат и возвращает черновик. Учитель проверяет каждое задание и каждый слайд.
Почему нет автотестов? Честно: пока проверял вручную, линтером и сборкой. Следующий шаг — тесты для генератора, rng и шкалы оценок.
Прогресс потеряется? Да, если очистить браузер или зайти с другого устройства. Это плата за отсутствие аккаунтов и сбора данных.
Скрытие материала — это античит? Нет. Это режим самопроверки. Для настоящего античита нужен сервер, который выдаёт вопросы и принимает ответы.
Сколько стоит сайт? Домен — примерно 200–300 рублей в год. GitHub Pages и Cloudflare Pages бесплатны. Workers AI — в пределах бесплатного дневного запаса, карта не нужна.
Что дальше? Тесты интерфейса, новые предметы и модули, синхронизация прогресса.

15. Что я понял по ходу

Самое полезное решение — разделить случайность и логику. Генератор чисел ничего не знает о задачах, а сборщик ничего не знает о том, как устроен mulberry32. Поэтому можно менять уровни и темы, не трогая генератор.

Второе — не тащить сервер туда, где он не нужен. Уроки, банк и печать работают в браузере. Это быстрее, дешевле и надёжнее для школы. Сервер появился только там, где без него нельзя, — для доступа к модели ИИ.

Третье — честные ограничения. Нет автотестов, прогресс не синхронизируется, скрытие материала не античит. Если говорить об этом прямо, на защите не придётся выкручиваться.

Если какой-то раздел всё равно непонятен — открой соответствующий файл и прочитай код рядом с комментариями. В проекте почти везде есть короткие пояснения по-русски.
