## 1. Паспорт проекта

| Параметр | Значение |
|---|---|
| Название | **Alma** — цифровой школьный помощник |
| Идея | Один сайт для двух сценариев: ученик разбирается в теме, учитель готовит проверочную работу или презентацию |
| Аудитория | Школьники и учителя-предметники |
| Что уже работает | 7 уроков по теории относительности, 3 интерактивные модели, квизы, итоговая работа с оценкой 2–5, банк заданий по физике, печать A4, презентации `.pptx`, генерация черновиков через ИИ, две темы оформления |
| ИИ | Cloudflare Pages Functions + Workers AI: бесплатный дневной запас, отдельный ключ не нужен, доступ к модели закрыт сервером |
| Стек | Vite, React 19, React Router 7, CSS без UI-библиотек, Canvas 2D, `pptxgenjs`, Cloudflare Pages Functions, Workers AI |
| Хостинг | GitHub Pages, статическая сборка; ИИ-часть — на Cloudflare Pages |
| Домен | `alma-edu.ru`, DNS на Timeweb, A-записи указывают на GitHub Pages |
| Главный принцип | Ядро работает без сервера; ИИ — только черновик, который проверяет учитель |

### 1.1. Одной фразой

Если коротко, Alma — это конструктор учебного цикла: объяснение, интерактивная модель, проверка, разбор ошибок и итоговая работа. У учителя своя часть: выбрать тему, сложность и количество заданий, а на выходе получить лист A4 с ключом и пояснениями.

### 1.2. Главное

1. **Основная часть работает без сервера.** Уроки, банк физики, проверки, печать и прогресс не требуют интернета. Школа может открыть сайт даже при плохой связи, а я не плачу за хостинг базы данных.
2. **Ответы не записаны в текст, а считаются формулами.** Генератор задачи сам вычисляет правильный ответ и подбирает правдоподобные неверные варианты.
3. **Один код варианта всегда даёт один и тот же набор заданий.** Учитель может пересоздать работу и получить тот же вариант.
4. **ИИ не ставит оценки и не печатает работу без человека.** Модель предлагает черновик, учитель правит его и только потом отправляет на печать.
5. **Доступ к модели не попадает в браузер.** Для ИИ написан отдельный серверный посредник на Cloudflare Pages: он принимает тему, добавляет методический промпт, вызывает Workers AI и проверяет ответ по формату. Ключа нет — модель работает на стороне Cloudflare, а бесплатный дневной запас защищён CORS и лимитами.

## 2. Что умеет проект

### 2.1. Сценарий ученика

- **7 уроков** по специальной теории относительности: от кризиса классической физики до `E = mc²`.
- **3 интерактивные модели** на Canvas 2D:
  - световые часы;
  - поезд и мяч (сложение скоростей);
  - вспышки молний и относительность одновременности.
- **Квиз после каждого урока**: 26 вопросов на весь модуль.
- **Итоговая работа**: 10 вопросов, оценка по школьной шкале 2–5, неограниченная пересдача.
- **Прогресс** сохраняется в `localStorage` браузера.
- Итоговая работа открывается только после прохождения всех семи уроков.

### 2.2. Сценарий учителя

- **Банк заданий по физике**: 7 тем и «Сборная работа по всем темам».
- **55 генераторов заданий**: у каждого свой уровень сложности и своя формула ответа.
- **До 20 заданий и 2 варианта** в одной работе.
- **Три уровня сложности**: базовый, смешанный, повышенный.
- **Печать A4**: лист с заданиями, паспорт работы, бланк ответов, отдельный ключ и пояснения.
- **Презентации к уроку**: черновик структуры, редактирование слайдов, скачивание в **редактируемый `.pptx`**.
- **Черновики по любому предмету** через ИИ: алгебра, русский язык, биология, история и т. д. — с обязательной проверкой учителем.

### 2.3. Чего в проекте сознательно нет

- Нет регистрации и аккаунтов.
- Нет базы данных и серверного журнала оценок.
- Нет автоматической проверки открытых ответов.
- Нет «чата с ИИ» — ИИ используется только как генератор черновика.
- Нет попытки заменить учителя: оценки выставляет человек.

## 3. Архитектура проекта

### 3.1. Общая схема

```
Пользователь
    │
    ▼
React SPA (Vite)
    ├── Ученик: уроки → симуляции → квиз → итоговая работа
    │       └── прогресс в localStorage
    │
    ├── Учитель: банк физики → генератор варианта → печать A4
    │       └── всё считается в браузере, без сервера
    │
    └── Учитель: ИИ-черновик → проверка → печать / .pptx
            └── Cloudflare Pages Function → Workers AI
                    └── модель работает на стороне Cloudflare
```

### 3.2. Почему я выбрал такую архитектуру

| Решение | Причина |
|---|---|
| Статический SPA на GitHub Pages | Бесплатный хостинг, нечего администрировать, быстро открывается |
| Банк заданий в браузере | Работает без интернета, нет задержки, нет оплаты за сервер |
| `localStorage` для прогресса | Не нужны аккаунты и персональные данные |
| Отдельный серверный посредник для ИИ | Прямой доступ к модели из браузера увидит любой пользователь, а бесплатный лимит быстро закончится |
| `HashRouter` | GitHub Pages не умеет перенаправлять все адреса на `index.html`; хэш решает проблему обновления страницы |
| Canvas 2D | Нет тяжёлых 3D-библиотек; модели быстро работают на школьных ноутбуках |
| `pptxgenjs` | Презентация собирается на устройстве учителя, текст остаётся редактируемым |

### 4.1. Навигация без сервера: `HashRouter`

**Задача.** Сайт лежит на GitHub Pages. Это статический хостинг: он отдаёт файлы, но не умеет, как сервер, перенаправлять любой адрес на `index.html`. Если открыть `/modules/relativity` и нажать F5, GitHub Pages попытается найти такую папку и вернёт 404.

**Идея.** Хэш-часть адреса (`#/modules/relativity`) не отправляется на сервер. Браузер всегда запрашивает только `index.html`, а маршрут разбирает React Router уже внутри страницы. Поэтому обновление работает.

**Код.**

`src/main.jsx`, строки 3–11:

```jsx
import { HashRouter } from 'react-router-dom'

createRoot(document.getElementById('root')).render(
  <StrictMode>
    <HashRouter>
      <App />
    </HashRouter>
  </StrictMode>,
)
```

`src/App.jsx`, строки 16–26:

```jsx
<Routes>
  <Route path="/" element={<HomePage />} />
  <Route path="/modules" element={<ModulesPage />} />
  <Route path="/teacher" element={<TeacherPage />} />
  <Route path="/teacher/presentation" element={<PresentationPage />} />
  <Route path="/modules/:moduleId" element={<ModulePage />} />
  <Route path="/modules/:moduleId/exam" element={<ModuleExamPage />} />
  <Route path="/modules/:moduleId/:lessonId" element={<LessonPage />} />
  <Route path="/about" element={<AboutPage />} />
  <Route path="*" element={<NotFoundPage />} />
</Routes>
```

**Что здесь главное.** Я сознательно отказался от «красивых» адресов без решётки. За них пришлось бы платить отдельным сервером или настраивать сложный fallback. Для школьного проекта важнее надёжность и нулевая стоимость хостинга. Дополнительно workflow копирует `index.html` в `404.html` — это запасной вариант, если пользователь всё-таки попадёт на неизвестный адрес.

**Компромисс.** В адресной строке есть `#`. Для школьного проекта это нормальная плата за бесплатный и надёжный хостинг.

### 4.2. Тема без «мигания»: скрипт до первой отрисовки

**Задача.** Пользователь выбирает светлую или тёмную тему. Нужно, чтобы при загрузке страница не мигала белым, а тема сохранялась между визитами.

**Идея.** Тема хранится в `localStorage` под ключом `alma-theme`. Маленький inline-скрипт в `index.html` выполняется **до** отрисовки body: читает сохранённое значение или системную настройку `prefers-color-scheme` и сразу ставит `data-theme` на `<html>`.

**Код.**

`index.html`, строки 19–39:

```html
<script>
  // Ставим тему до первой отрисовки, чтобы страница не мигала.
  ;(function () {
    try {
      var saved = localStorage.getItem('alma-theme')
      var theme =
        saved === 'light' || saved === 'dark'
          ? saved
          : window.matchMedia('(prefers-color-scheme: dark)').matches
            ? 'dark'
            : 'light'
      document.documentElement.dataset.theme = theme
      var meta = document.querySelector('meta[name="theme-color"]')
      if (meta) {
        meta.setAttribute('content', theme === 'light' ? '#f7f5ef' : '#171a1d')
      }
    } catch (error) {
      // Приватный режим может запрещать localStorage — оставляем тему по умолчанию.
    }
  })()
</script>
```

`src/lib/useTheme.js`, строки 5–18 и 23–45:

```js
function getInitialTheme() {
  if (typeof window === 'undefined') return 'light'

  try {
    const saved = localStorage.getItem(STORAGE_KEY)
    if (saved === 'light' || saved === 'dark') return saved
  } catch {
    // localStorage может быть недоступен в приватном режиме.
  }

  return window.matchMedia('(prefers-color-scheme: dark)').matches
    ? 'dark'
    : 'light'
}

export function useTheme() {
  const [theme, setTheme] = useState(getInitialTheme)

  useEffect(() => {
    document.documentElement.dataset.theme = theme

    try {
      localStorage.setItem(STORAGE_KEY, theme)
    } catch {
      // Ничего страшного: тема просто не запомнится.
    }

    const meta = document.querySelector('meta[name="theme-color"]')
    if (meta) {
      meta.setAttribute('content', theme === 'light' ? '#f7f5ef' : '#171a1d')
    }
  }, [theme])

  function toggleTheme() {
    setTheme((current) => (current === 'light' ? 'dark' : 'light'))
  }

  return { theme, toggleTheme }
}
```

**Как устроены стили.** В `src/index.css` объявлены семантические переменные:

```css
:root {
  --color-bg: #171a1d;
  --color-surface: #20252a;
  --color-text: #e8ecea;
  --color-accent: #3fae76;
  --font-display: "Iowan Old Style", "Palatino Linotype", Georgia,
    "Times New Roman", serif;
}

:root[data-theme="light"] {
  --color-bg: #f7f5ef;
  --color-surface: #fffdf8;
  --color-text: #20251f;
  --color-accent: #2f7d55;
}
```

Компоненты не знают, светлая тема сейчас или тёмная: они используют `var(--color-bg)` и т. п. Поэтому переключение темы — это смена одного атрибута, а не перерисовка всех компонентов.

**Что здесь главное.** Тема не хранится в React-состоянии «на сервере» и не требует аккаунта. Это чисто клиентское решение. Если `localStorage` запрещён в приватном режиме, сайт всё равно работает — просто не запомнит выбор.

### 4.3. Прогресс ученика и разблокировка итоговой работы

**Задача.** Показать, какие уроки пройдены, и не пускать к итоговой работе, пока не пройден весь модуль.

**Идея.** Прогресс — это обычный JSON-объект в `localStorage`:

```json
{
  "relativity/classical-crisis": true,
  "relativity/reference-frames": true
}
```

Ключ — `moduleId/lessonId`. Значение — `true`, если урок пройден.

**Код.**

`src/lib/progress.js`, строки 1–19:

```js
const STORAGE_KEY = 'alma-progress'

export function getProgress() {
  try {
    return JSON.parse(localStorage.getItem(STORAGE_KEY)) || {}
  } catch {
    return {}
  }
}

export function isLessonDone(moduleId, lessonId) {
  return Boolean(getProgress()[`${moduleId}/${lessonId}`])
}

export function markLessonDone(moduleId, lessonId) {
  const progress = getProgress()
  progress[`${moduleId}/${lessonId}`] = true
  localStorage.setItem(STORAGE_KEY, JSON.stringify(progress))
}
```

`src/pages/ModuleExamPage.jsx`, строки 22–26:

```jsx
const doneLessons = module.lessons.filter((lesson) =>
  isLessonDone(module.id, lesson.id),
)
const unlocked = doneLessons.length === module.lessons.length
```

**Тонкость.** Урок отмечается пройденным, когда ученик **проверил все вопросы квиза**, а не когда ответил на 100% правильно. Это сделано специально: цель — не наказать за ошибку, а провести через материал. Итоговая оценка считается отдельно по проценту правильных ответов.

**Ограничение.** Прогресс хранится только в этом браузере. Если очистить данные сайта или зайти с другого устройства, прогресс начнётся заново. Это плата за отсутствие аккаунтов. В будущем можно добавить вход и синхронизацию, но это уже требует базы данных и защиты персональных данных.

### 4.4. Квиз: скрытие материала, проверка и пересдача

**Задача.** Ученик не должен подсматривать в текст урока во время проверки. После ответа нужно показать, верно ли решено, и объяснить почему.

**Идея.** Квиз — это маленькая машина состояний:

```
не начат
  → начат (текст урока скрыт)
  → выбран ответ
  → проверен вопрос (показан разбор)
  → проверены все вопросы
  → результат и оценка
  → «Пройти ещё раз» (сброс)
```

**Код.**

`src/components/Quiz/Quiz.jsx`, строки 6–11:

```js
function gradeFor(ratio) {
  if (ratio >= 0.9) return 5
  if (ratio >= 0.75) return 4
  if (ratio >= 0.6) return 3
  return 2
}
```

```jsx
    (question) => checked[question.id] && selected[question.id] === question.correct,
  ).length
  const ratio = questions.length > 0 ? score / questions.length : 0

  useEffect(() => {
    if (!allChecked) return
    const match = location.pathname.match(/^\/modules\/([^/]+)\/([^/]+)$/)
    if (match) {
      markLessonDone(match[1], match[2])
    }
  }, [allChecked, location.pathname])
```

### 4.6. Генератор вариантов: детерминированный случай

**Задача.** Учитель нажимает «Собрать работу» — и каждый раз получает новый набор заданий. При этом должен быть способ воспроизвести тот же вариант: например, если нужно распечатать заново или проверить, что у соседа по парте другой вариант.

**Идея.** Используется не `Math.random()`, а **детерминированный генератор mulberry32** с числовым seed. Один и тот же seed и одна и та же последовательность обращений к генератору дают один и тот же результат.

**Код.**

`src/teacher/rng.js`, строки 1–36:

```js
// Детерминированный генератор случайных чисел (mulberry32).
// Нужен для того, чтобы один и тот же "код варианта" всегда давал
// один и тот же набор заданий: учитель может пересоздать работу.

export function makeRng(seed) {
  let state = (seed >>> 0) || 1

  function next() {
    state = (state + 0x6d2b79f5) >>> 0
    let t = state
    t = Math.imul(t ^ (t >>> 15), t | 1)
    t ^= t + Math.imul(t ^ (t >>> 7), t | 61)
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296
  }

  function int(min, max) {
    return min + Math.floor(next() * (max - min + 1))
  }

  function pick(list) {
    return list[int(0, list.length - 1)]
  }

  function shuffle(list) {
    const result = [...list]
    for (let i = result.length - 1; i > 0; i -= 1) {
      const j = int(0, i)
      const temp = result[i]
      result[i] = result[j]
      result[j] = temp
    }
    return result
  }

  return { next, int, pick, shuffle }
}
```

**Как выбирается seed.** В `src/teacher/buildTest.js`, строки 149–167:

```js

  topicId,
  count = 10,
  difficultyId = 'mixed',
  variantCount = 1,

```

**Что здесь главное.**

- `seedBase` — случайное число от 100000 до 999999. Оно печатается внизу листа как «код варианта».
- Второй вариант получает seed `base + 7919`, поэтому набор заданий отличается, но остаётся воспроизводимым.
- `shuffle` — это Fisher–Yates: честное перемешивание, каждый элемент может оказаться на любом месте.
- Генератор не «запоминает» задания между запусками. Воспроизводимость обеспечивается только seed и порядком вызовов.

**Почему это интересно.** Я отделил **источник случайности** от **логики выбора**. Логика может меняться (например, добавляться новые уровни), а seed останется тем же. Это как «зерно» в Minecraft: одно число задаёт целый мир.

### 4.7. Распределение заданий по сложности: квоты и метод наибольших остатков

**Задача.** Учитель просит, например, 10 заданий смешанной сложности. Нужно получить не «сколько получится», а точное количество: 50% базовых, 35% повышенных, 15% высоких — с округлением до целых.

**Идея.** Для каждого уровня считается доля:

```
доля × количество = целая часть + дробный остаток
```

Сначала берётся целая часть. Потом «лишние» задания распределяются по одному тем уровням, у кого дробный остаток больше. Это классический метод наибольших остатков (largest remainder).

**Код.**

```js
}

  { id: 'basic', label: 'Базовый', mix: { basic: 1 } },

    label: 'Смешанный',
```

`src/teacher/buildTest.js`, строки 29–47:

```js
function quotaFor(count, mix) {
  const rows = Object.entries(mix).map(([level, share]) => ({
    level,
    whole: Math.floor(share * count),
    remainder: share * count - Math.floor(share * count),
  }))

  let left = count - rows.reduce((sum, row) => sum + row.whole, 0)
  const byRemainder = [...rows].sort((a, b) => b.remainder - a.remainder)

  let index = 0
  while (left > 0) {
    byRemainder[index % byRemainder.length].whole += 1
    index += 1
    left -= 1
  }

  return Object.fromEntries(rows.map((row) => [row.level, row.whole]))
}
```

**Что здесь главное.** Если просто округлить каждую долю, сумма может не совпасть с нужным количеством (например, 5 + 4 + 2 = 11 вместо 10). Метод остатков гарантирует ровно `count` заданий. При этом более сложные уровни не «пропадают» из-за округления вниз.

**Пример.** Для 10 заданий и микса 50/35/15: базовых 5, повышенных 3,5, высоких 1,5. Целые части дают 5 + 3 + 1 = 9. Одно оставшееся задание уходит уровню с большим остатком. В текущей реализации это повышенный уровень — получается 5 / 4 / 1. Главное — сумма всегда ровно 10.

### 4.8. Выбор заданий без повторов и запасной добор

**Задача.** В одном варианте не должно быть двух одинаковых задач. Если в выбранном уровне не хватает генераторов, нужно добрать из других уровней, но не зациклиться.

**Идея.**

1. Для каждого уровня берётся свой пул генераторов.
2. Пул перемешивается.
3. Кандидат принимается, только если у него ровно 3 неверных варианта и текст ещё не встречался.
4. На одну позицию даётся до 40 попыток.
5. Если после всех уровней заданий меньше нужного — добираем из всех генераторов, но не более 500 попыток.
6. В конце сортируем «от простого к сложному».

**Код.**

`src/teacher/buildTest.js`, строки 49–104:

```js
function buildVariant(topic, { count, difficultyId, seed }) {
  const rng = makeRng(seed)
  const difficulty =
    DIFFICULTIES.find((item) => item.id === difficultyId) || DIFFICULTIES[1]
  const quota = quotaFor(count, difficulty.mix)
  const used = new Set()
  const items = []

  LEVEL_ORDER.forEach((level) => {
    const need = quota[level] || 0
    if (need === 0) return

    let pool = topic.generators.filter((generator) => generator.level === level)
    if (pool.length === 0) pool = topic.generators

    let order = rng.shuffle(pool)
    let cursor = 0

    for (let i = 0; i < need; i += 1) {
      let draft = null

      for (let attempt = 0; attempt < 40; attempt += 1) {
        if (cursor >= order.length) {
          cursor = 0
          order = rng.shuffle(pool)
        }

        const generator = order[cursor]
        cursor += 1
        const candidate = generator.build(rng)

        if (
          candidate &&
          candidate.distractors.length === 3 &&
          !used.has(candidate.text)
        ) {
          draft = candidate
          break
        }
      }

      if (!draft) return

      used.add(draft.text)
      const options = rng.shuffle([draft.correct, ...draft.distractors])

      items.push({
        level,
        points: LEVELS[level].points,
        text: draft.text,
        options,
        correctIndex: options.indexOf(draft.correct),
        explanation: draft.explanation,
      })
    }
  })
```

`src/teacher/buildTest.js`, строки 106–146:

```js
  // Если заданий выбранного уровня не хватило (например, учитель просит
  // 20 задач по узкой теме), добираем из остальных уровней.
  if (items.length < count) {
    let guard = 0

    while (items.length < count && guard < 500) {
      guard += 1
      const generator = rng.pick(topic.generators)
      const candidate = generator.build(rng)

      if (
        !candidate ||
        candidate.distractors.length !== 3 ||
        used.has(candidate.text)
      ) {
        continue
      }

      used.add(candidate.text)
      const options = rng.shuffle([candidate.correct, ...candidate.distractors])

      items.push({
        level: generator.level,
        points: LEVELS[generator.level].points,
        text: candidate.text,
        options,
        correctIndex: options.indexOf(candidate.correct),
        explanation: candidate.explanation,
      })
    }
  }

  // Сохраняем порядок «от простого к сложному».
  items.sort(
    (first, second) =>
      LEVEL_ORDER.indexOf(first.level) - LEVEL_ORDER.indexOf(second.level),
  )

  const totalPoints = items.reduce((sum, item) => sum + item.points, 0)

  return { seed, items, totalPoints }
}
```

**Что здесь главное.**

- `used` — это `Set` текстов заданий. Проверка `!used.has(candidate.text)` не даёт повторов.
- Счётчики `40` и `500` — защита от бесконечного цикла. Если генератор по каким-то причинам не может выдать корректную задачу, программа не зависает.
- `cursor` и повторное перемешивание пула позволяют обойти все генераторы, а не крутиться на первых трёх.
- Сортировка в конце нужна, чтобы лист шёл от простого к сложному, даже если внутри уровней задания выбирались случайно.
- В интерфейсе есть предупреждение: для работы длиннее 8 заданий по одной узкой теме лучше выбрать «Сборную работу по всем темам». Это не ограничение алгоритма, а подсказка учителю.

### 4.9. Правдоподобные неверные ответы

**Задача.** В тесте не должно быть вариантов «42», «—7», «всё перечисленное». Неверные ответы должны быть похожи на реальные ошибки ученика.

**Идея.** Правильный ответ вычисляется формулой. Неверные варианты — это:

- типичные арифметические ошибки (забыл разделить, умножил вместо деления);
- результат с перепутанными единицами;
- удвоенное/утроенное значение;
- специально переданные значения для конкретной задачи.

**Код.**

`src/teacher/topics/helpers.js`, строки 1–27:

```js
import { formatNumber } from '../format'

// Собирает варианты ответа для вычислительной задачи.
// Главный ответ считается формулой, а "неверные" берутся из типичных
// ошибок: забыл разделить, перепутал операцию, не перевёл единицы.
export function numericAnswer(value, unit, extraValues = []) {
  const suffix = unit ? ` ${unit}` : ''
  const correct = `${formatNumber(value)}${suffix}`
  const seen = new Set([formatNumber(value)])
  const distractors = []

  function tryAdd(raw) {
    if (distractors.length >= 3) return
    if (!Number.isFinite(raw) || raw <= 0) return

    const text = formatNumber(raw)
    if (seen.has(text)) return

    seen.add(text)
    distractors.push(`${text}${suffix}`)
  }

  const candidates = [...extraValues, value * 2, value / 2, value * 3, value / 4]
  candidates.forEach(tryAdd)

  return { correct, distractors }
}
```

`src/teacher/format.js`, строки 1–16:

```js
// Числа в русской записи: запятая вместо точки, пробел между тысячами.
// Округляем до трёх знаков — школьных задач с большей точностью не бывает.

export function formatNumber(value) {
  if (!Number.isFinite(value)) return '—'

  const rounded = Math.round(value * 1000) / 1000
  const fixed = Number.isInteger(rounded)
    ? String(rounded)
    : rounded.toFixed(3).replace(/0+$/, '').replace(/\.$/, '')

  const [intPart, fracPart] = fixed.split('.')
  const grouped = intPart.replace(/\B(?=(\d{3})+(?!\d))/g, '\u00A0')

  return fracPart ? `${grouped},${fracPart}` : grouped
}
```

**Что здесь главное.**

- Если изменить числа в генераторе, правильный ответ и неверные варианты пересчитаются автоматически.
- `formatNumber` делает числа по-русски: `12,5` вместо `12.5`, `1 000` с неразрывным пробелом.
- Неверные варианты фильтруются: они должны быть положительными и не совпадать с правильным. Если кандидатов не хватает, добавятся следующие из списка.

**Честное ограничение.** Генератор проверяет **формат** и **вычисление**, но не проверяет, что задача методически идеальна для конкретного класса. Поэтому в учительской есть предупреждения, а в ИИ-режиме — обязательная проверка человеком.

### 4.10. Шкала оценок для работы учителя

**Задача.** В работе есть задания разного уровня: базовое — 1 балл, повышенное — 2, высокое — 3. Оценка должна зависеть от суммы баллов, а не от количества заданий.

**Идея.** Считаем максимальный балл и берём пороги:

- «5» — от 85% максимума;
- «4» — от 70%;
- «3» — от 50%;
- ниже 50% — «2».

**Код.**

`src/teacher/buildTest.js`, строки 170–178:

```js
// Пороги оценок. Считаем от максимального балла, а не от числа
// заданий: задания разного уровня весят по-разному.
export function gradeScale(totalPoints) {
  return {
    five: Math.ceil(totalPoints * 0.85),
    four: Math.ceil(totalPoints * 0.7),
    three: Math.ceil(totalPoints * 0.5),
  }
}
```

**Что здесь главное.** `Math.ceil` округляет вверх: порог не может быть дробным. Например, если максимум 17 баллов, «5» начинается с 15 (14,45 → 15). Это делает шкалу понятной и не занижает оценку из-за округления.

**Отличие от ученической шкалы.** У ученика пороги считаются от **доли правильных ответов** (90/75/60), потому что все вопросы итоговой работы равны. У учителя — от **суммы баллов**, потому что задания разного уровня. Это два разных алгоритма, и это нормально: у них разные цели.

**Что здесь главное.**

- `@page { size: A4; margin: 0; }` говорит браузеру, что это A4.
- `.no-print` скрывает кнопки, подсказки и навигацию — на бумаге остаётся только работа.
- `page-break-after: always` ставит каждый вариант и ключ на отдельную страницу.
- `break-inside: avoid` не даёт заданию или строке ключа разорваться между страницами.
- Ключ ответов — отдельный `<article>`, поэтому его можно не печатать ученикам: достаточно выбрать диапазон страниц в диалоге печати.

**Состав листа.** `src/teacher/TestSheet.jsx`, строки 6–45: шапка с школой и датой, заголовок, тема, класс/учитель/вариант, поле для фамилии, паспорт работы (заданий, время, максимум), шкала, инструкция. Строки 72–83 — бланк ответов. Строки 92–137 — ключ с ответами, баллами и (опционально) пояснениями.

**Что здесь главное.** Печать — это не отдельный PDF-генератор. Используется системный диалог браузера «Печать → Сохранить как PDF». Поэтому не нужна библиотека PDF и не нужно платить за сервер. Учитель может выбрать принтер или сохранить файл.

### 4.12. Экспорт `.pptx`: редактируемая презентация

**Задача.** Учитель хочет не картинку слайда, а нормальную презентацию, которую можно открыть в PowerPoint, Keynote или «Р7-Офис» и отредактировать.

**Идея.** `pptxgenjs` собирает файл прямо в браузере. Каждый слайд — это текстовые блоки и векторные фигуры, а не скриншот. Поэтому текст остаётся текстом, а цветную полосу можно двигать.

**Код.**

`src/teacher/presentation.js`, строки 240–263:

```js
export async function downloadPresentation({ meta, slides }) {
  const module = await import('pptxgenjs')
  const PptxGenJS = module.default

  const pptx = new PptxGenJS()
  pptx.layout = 'LAYOUT_WIDE'
  pptx.author = 'Alma'
  pptx.company = 'Alma'
  pptx.subject = meta.subjectTitle
  pptx.title = meta.topicTitle

  const total = slides.length

  slides.forEach((item, index) => {
    const slide =
      index === 0
        ? addTitleSlide(pptx, meta, item)
        : addContentSlide(pptx, meta, item, index + 1, total)

    if (item.note) slide.addNotes(item.note)
  })

  await pptx.writeFile({ fileName: `${fileBaseName(meta)}.pptx` })
}
```

**Что происходит внутри.**

- `LAYOUT_WIDE` — формат 16:9, 13,333 × 7,5 дюйма.
- Первый слайд — титульный: тема, предмет, класс, дата.
- Остальные — заголовок, акцентная линия, список пунктов, колонтитул с номером слайда.
- Если пунктов много или они длинные, размер шрифта автоматически уменьшается: `bulletLength > 320 || bullets.length > 5 ? 16 : 19`.
- Заметки докладчика (`note`) добавляются в заметки слайда, а не на экран.
- Имя файла очищается от запрещённых символов и обрезается до 90 символов.

**Почему динамический импорт.** `pptxgenjs` — тяжёлая библиотека. Она загружается только в момент экспорта, а не при открытии сайта. В production-сборке она вынесена в отдельный чанк (`pptxgen.es-*.js`), поэтому уроки и учительская форма открываются быстрее.

**Что здесь главное.** В презентацию **не вставляются картинки**. Это сделано специально: текст и фигуры остаются редактируемыми, файл получается компактным, а учитель может свободно менять оформление. Если понадобятся изображения, их можно добавить отдельным шагом, но это уже другая задача.

**Генерация слайдов.** Слайды приходят из ИИ-черновика (см. 4.13). Сам экспорт `.pptx` работает независимо: если у учителя уже есть массив слайдов, файл собирается без сети.

### 4.13. ИИ-генератор: Cloudflare Pages, Workers AI и проверка на клиенте

**Задача.** Хотим, чтобы учитель мог получить черновик заданий по любому предмету, но:

- доступ к модели не должен попадать в браузер;
- посторонний не должен тратить бесплатный дневной запас;
- модель не должна сломать вёрстку плохим ответом;
- учитель должен видеть, что это черновик, а не готовая работа.

**Почему Cloudflare.** Сайт лежит на GitHub Pages, а там нет PHP. Держать ключ модели в JavaScript нельзя. Поэтому серверная часть вынесена на Cloudflare Pages Functions: это бесплатно, не требует карты и отдельного хостинга. Модель запускается через Workers AI — она работает на стороне Cloudflare, поэтому ключ вообще не нужен. Бесплатный план даёт 10 000 Neurons в сутки; этого хватает на несколько десятков черновиков.

**Идея.** Схема из двух проверок:

```
Браузер → POST /api/generate → Cloudflare Pages Function → Workers AI
                │
                ├── CORS: только свои сайты
                ├── валидация входа
                ├── лимит 20 запросов в час с одного IP
                ├── строгий промпт
                ├── таймаут 65 секунд
                ├── разбор JSON
                └── проверка каждого задания
                        │
                        ▼
Браузер ← JSON с заданиями
    │
    ├── повторная проверка формата
    └── экран «Проверка черновика» → учитель правит → печать
```

**Код: CORS и метод.** `cloudflare/worker.js`, строки 54–85:

```js
  const origin = request.headers.get('Origin') || ''
  const cors = corsHeaders(origin)

  if (request.method === 'OPTIONS') {
```

```js
    'Access-Control-Max-Age': '86400',
```

```js
function parseItems(data) {
  if (!Array.isArray(data?.items)) {
    throw new HttpError(
      502,
      'В ответе модели нет списка заданий. Попробуйте ещё раз.',
    )
  }

  const levels = ['basic', 'advanced', 'high']
  const items = []

  for (const raw of data.items) {
    if (!raw || typeof raw !== 'object') continue

    const text = clean(raw.text, 600)

    if (!text) continue

    const options = Array.isArray(raw.options)
      ? raw.options.slice(0, 4).map((option) => clean(option, 200)).filter(Boolean)
      : []

    // Ровно четыре разных варианта — иначе задание не печатаем.
    if (options.length !== 4 || new Set(options).size !== 4) continue

    let correct = raw.correctIndex

    if (typeof correct === 'string' && /^\d+$/.test(correct)) {
      correct = Number(correct)
    }

    if (!Number.isInteger(correct) || correct < 0 || correct > 3) continue

    const level = levels.includes(raw.level) ? raw.level : 'basic'
    const explanation = clean(raw.explanation, 600)
    const check = raw.check === 'mismatch' ? 'mismatch' : 'ok'

    items.push({
      text,
      options,
      correctIndex: correct,
      explanation,
      level,
      check,
    })
  }

  if (items.length === 0) {
    throw new HttpError(
      502,
      'Модель вернула задания в неизвестном формате. Попробуйте ещё раз.',
    )
  }

  // Печатаем от простого к сложному, как в банке Alma.
  const order = { basic: 0, advanced: 1, high: 2 }
  items.sort((first, second) => order[first.level] - order[second.level])

  return items.slice(0, 15)
}
```

**Код: повторная проверка на клиенте.**

```js
function normalize(payload) {
  const rawItems = Array.isArray(payload?.items) ? payload.items : []
  const warnings = []
  const items = []

  rawItems.forEach((raw) => {
    const text = String(raw?.text ?? '').trim()
    const options = Array.isArray(raw?.options)
      ? raw.options.map((option) => String(option).trim())
      : []
    const correctIndex = Number(raw?.correctIndex)
    const explanation = String(raw?.explanation ?? '').trim()
    const level = LEVELS[raw?.level] ? raw.level : 'basic'

    const valid =
      text.length > 0 &&
      options.length === 4 &&
      new Set(options).size === 4 &&
      Number.isInteger(correctIndex) &&
      correctIndex >= 0 &&
      correctIndex <= 3

    if (!valid) return

    items.push({
      text,
      options,
      correctIndex,
      explanation,
      level,
      points: LEVELS[level].points,
      needsCheck: raw?.check === 'mismatch',
    })
  })

  const dropped = rawItems.length - items.length
  if (dropped > 0) {
    warnings.push(
      `Отброшено заданий с некорректным форматом: ${dropped}. Попробуйте сгенерировать ещё раз.`,
    )
  }

  const mismatched = items.filter((item) => item.needsCheck).length
  if (mismatched > 0) {
    warnings.push(
      `${mismatched} заданий не прошли самопроверку — они отмечены и требуют вашего внимания.`,
    )
  }

  return { items, warnings }
}
```

**Что здесь главное.**

- Ключа модели нет: используется Workers AI, модель работает на стороне Cloudflare. В браузер уходит только результат, а не доступ к модели.
- CORS разрешает только адреса из белого списка: `alma-edu.ru`, `www.alma-edu.ru`, `qqquies.github.io`, `localhost:5173` и `127.0.0.1:5173`.
- Лимит — **20 запросов в час с одного IP**. Он живёт в памяти экземпляра Worker и сбрасывается при перезапуске; основной ограничитель — дневной запас Workers AI.
- Таймаут модели — **65 секунд**, таймаут фронтенда — **75 секунд**. Если модель не успела, учитель видит понятное сообщение и может попробовать снова.
- Промпт говорит модели: тема учителя — это **данные**, а не команда. Это защита от prompt injection.
- Отдельное правило требует **проверить арифметику подстановкой** и показать проверку в объяснении. Это снижает число ошибок, но не отменяет проверку человеком.
- Сервер проверяет: ровно 4 варианта, все разные, `correctIndex` от 0 до 3, уровень из белого списка. Битые задания отбрасываются, ответ сортируется от простого к сложному.
- Клиент проверяет ещё раз. Если модель вернула мусор, учитель увидит предупреждение, а не сломанную вёрстку.
- Задания с `check: "mismatch"` помечаются в интерфейсе как «проверить ответ». Это не автоматическая оценка, а сигнал учителю.

**Текущий статус.** ИИ-часть **подключена и работает**. Основной адрес — `https://alma-ai-73x.pages.dev/api/generate`, он прописан в `.env.production`. Генерация 5 заданий занимает примерно 20–40 секунд, 8 слайдов — около 20–25 секунд. Модель по умолчанию — `@cf/meta/llama-3.3-70b-instruct-fp8-fast`. Проверены оба сценария: «Проверка черновика» с выбором верного ответа и «Проверка презентации» с редактируемыми слайдами.

**Честное ограничение.** Модель может ошибиться в арифметике или формулировке. На одном из первых прогонов она неверно отметила ответ в линейном уравнении. Поэтому ИИ не печатает работу сам: учитель проверяет каждое задание и каждый слайд. Это не формальность, а обязательный шаг.

**Запасной вариант.** В `cloudflare/` остаётся обычный Worker, а в `server/` — PHP-прокси. Они нужны, если основной адрес недоступен или проект переедет на хостинг с PHP. Код промптов и проверки общий.

### 4.14. Анимация на Canvas: `requestAnimationFrame` и `dt`

**Задача.** Модели должны двигаться плавно и одинаково быстро на разных мониторах, не «прыгать» после переключения вкладки и не грузить процессор, когда пользователь поставил паузу.

**Идея.** Общий хук `useAnimationFrame` вызывает переданную функцию на каждом кадре и передаёт **время с прошлого кадра** в секундах. Все движения умножаются на `dt`, а не на фиксированное число.

**Код.**

`src/lib/useAnimationFrame.js`, строки 3–25:

```js
export default function useAnimationFrame(callback, active = true) {
  const callbackRef = useRef(callback)

  useEffect(() => {
    callbackRef.current = callback
  })

  useEffect(() => {
    if (!active) return undefined

    let frameId
    let lastTime = performance.now()

    const loop = (now) => {
      const dt = Math.min((now - lastTime) / 1000, 0.05)
      lastTime = now
      callbackRef.current(dt)
      frameId = requestAnimationFrame(loop)
    }

    frameId = requestAnimationFrame(loop)
    return () => cancelAnimationFrame(frameId)
  }, [active])
}
```

**Что здесь главное.**

- `callbackRef` обновляется на каждом рендере. Это позволяет анимации видеть свежие значения слайдеров, но не перезапускать цикл при каждом изменении состояния.
- `dt` ограничен `0.05` секунды. Если вкладка была свёрнута 10 секунд, без ограничения объект телепортировался бы через весь экран. С ограничением движение продолжится плавно.
- `active` — это пауза. Когда `active = false`, эффект не создаёт новый кадр, и браузер не тратит ресурсы.
- `cancelAnimationFrame` в очистке предотвращает утечку кадров при размонтировании.
- Canvas масштабируется под `devicePixelRatio`, чтобы линии были чёткими на Retina-экранах:

```js
const dpr = window.devicePixelRatio || 1
canvas.width = VIEW_W * dpr
canvas.height = VIEW_H * dpr
canvas.getContext('2d').scale(dpr, dpr)
```

**Почему Canvas, а не DOM/SVG.** В моделях много линий, кругов и следов, которые меняются каждый кадр. Canvas рисует их в одном буфере и не создаёт тысячи DOM-узлов. Для школьного ноутбука это заметно легче.

### 4.15. Световые часы: замедление времени через `gamma`

**Задача.** Показать, почему у движущихся часов период между отражениями больше, чем у покоящихся.

**Идея.** В модели есть два одинаковых «световых часа»: одни стоят, другие едут вправо. У покоящихся фотон проходит расстояние между зеркалами за `HALF_TICK = SPAN / PHOTON_SPEED`. У движущихся тот же цикл растягивается в `gamma` раз:

```
gamma = 1 / sqrt(1 - beta²)
tau = gamma * HALF_TICK
```

**Код.**

`src/modules/relativity/LightClockSim.jsx`, строки 105–143:

```jsx
useAnimationFrame((dt) => {
  const gamma = 1 / Math.sqrt(1 - beta * beta)
  const tau = gamma * HALF_TICK

  restY.current += restDir.current * PHOTON_SPEED * dt
  if (restY.current >= MIRROR_BOTTOM) {
    restY.current = MIRROR_BOTTOM
    restDir.current = -1
    restCountRef.current += 1
    setRestCount(restCountRef.current)
  } else if (restY.current <= MIRROR_TOP) {
    restY.current = MIRROR_TOP
    restDir.current = 1
    restCountRef.current += 1
    setRestCount(restCountRef.current)
  }

  movPhase.current += dt
  if (movPhase.current >= tau) {
    movPhase.current -= tau
    movDir.current *= -1
    movCountRef.current += 1
    setMovCount(movCountRef.current)
  }
  const p = Math.min(movPhase.current / tau, 1)
  const movY =
    movDir.current > 0 ? MIRROR_TOP + p * SPAN : MIRROR_BOTTOM - p * SPAN

  movX.current += beta * PHOTON_SPEED * dt
  if (movX.current > MOV_WRAP_X) {
    movX.current = MOV_START_X
    trail.current = []
  }

  trail.current.push({ x: movX.current, y: movY })
  if (trail.current.length > TRAIL_MAX) trail.current.shift()

  drawFrame(movY)
}, running)
```

**Что здесь главное.**

- `beta` — доля скорости света (`v/c`). Слайдер от 0 до 0,95.
- `gamma` при `beta = 0,6` равен 1,25; при `0,95` — примерно 3,20. Чем быстрее часы, тем сильнее растянут цикл.
- Счётчики отражений показывают, что за одно и то же время движущиеся часы «тикают» реже.
- След фотона рисуется как ломаная: он движется вверх-вниз и одновременно вправо вместе с часами.

**Где я упростил.** Это визуальная модель, а не численное решение уравнений Максвелла. Скорость света в ней условна (пиксели в секунду), а наклонный путь фотона не рассчитывается как отдельная траектория — я задаю растяжение периода через `gamma`. Для объяснения идеи этого достаточно; в тексте урока это отмечено.

### 4.16. Поезд и молнии: относительность одновременности

**Задача.** Показать, что две вспышки, одновременные для человека на платформе, не одновременны для пассажира движущегося поезда.

**Идея.** В момент `t = 0` в точках слева и справа от центра бьют молнии. Свет от каждой вспышки расходится кругом радиуса `r = c · t`. Поезд едет вправо со скоростью `v`. Пассажир находится в центре поезда и тоже движется.

События фиксируются, когда расстояние от источника до наблюдателя становится меньше радиуса круга:

```
|X_вспышки − X_наблюдателя| <= c · t
```

**Код.**

`src/modules/relativity/LightningTrainSim.jsx`, строки 47–49:

```js
function radius(t) {
  return LIGHT_SPEED * t
}
```

`src/modules/relativity/LightningTrainSim.jsx`, строки 190–235:

```jsx
useAnimationFrame(
  (dt) => {
    timeRef.current += dt
    const t = timeRef.current
    const v = vFracRef.current * LIGHT_SPEED
    const flags = flagsRef.current

    drawFrame(t)

    const passengerX = CENTER_X + v * t
    const distRight = Math.abs(RIGHT_X - passengerX)
    const distLeft = Math.abs(passengerX - LEFT_X)
    const newEvents = []

    if (!flags.passRight && distRight <= radius(t)) {
      flags.passRight = true
      newEvents.push({
        id: 'pass-right',
        label: `Правая вспышка достигла пассажира (${fmtTime(t)} с)`,
      })
    }
    if (!flags.platBoth && radius(t) >= STRIKE_DIST) {
      flags.platBoth = true
      newEvents.push({
        id: 'plat-both',
        label: `Обе вспышки достигли человека на платформе одновременно (${fmtTime(t)} с)`,
      })
    }
    if (!flags.passLeft && distLeft <= radius(t)) {
      flags.passLeft = true
      newEvents.push({
        id: 'pass-left',
        label: `Левая вспышка достигла пассажира (${fmtTime(t)} с)`,
      })
    }

    if (newEvents.length > 0) {
      setEvents((prev) => [...prev, ...newEvents])
    }

    if (flags.passRight && flags.platBoth && flags.passLeft) {
      setPhase('done')
    }
  },
  phase === 'running',
)
```

**Что здесь главное.**

- Свет от каждой вспышки идёт во все стороны с одинаковой скоростью. Поэтому на экране два расширяющихся круга.
- Человек на платформе стоит в центре: расстояния до вспышек равны, свет приходит одновременно.
- Пассажир едет вправо: правая вспышка оказывается ближе, левая — дальше. Поэтому правая вспышка достигает его раньше.
- Флаги `passRight`, `platBoth`, `passLeft` не дают событию записаться дважды.
- Когда все три события произошли, появляется вывод: «оба наблюдателя видят честную картину, но одновременность относительна».

**Где я упростил.** Скорости в модели преувеличены: настоящий поезд не может ехать со скоростью, сравнимой со скоростью света. Это сделано, чтобы эффект был виден за несколько секунд. Модель показывает принцип, а не реальный эксперимент.

### 4.17. Мяч в поезде: классическое сложение скоростей

**Задача.** Показать, что для человека на платформе скорость мяча складывается из скорости поезда и скорости мяча внутри вагона.

**Идея.** Поезд движется со скоростью `trainSpeed`, мяч внутри — со скоростью `ballSpeed`. Для наблюдателя на платформе:

```
v_мяча = trainSpeed + ballSpeed
```

**Код.**

`src/modules/relativity/BallTrainSim.jsx`, строки 173–190:

```jsx
useAnimationFrame((dt) => {
  const scaledDt = dt * TIME_ZOOM

  frontX.current += trainSpeed * scaledDt
  if (frontX.current - TOTAL_LEN > VIEW_W + 60) {
    frontX.current = -60
  }

  if (ballActive.current) {
    ballX.current += (trainSpeed + ballSpeed) * scaledDt
    if (ballX.current > VIEW_W + 30) {
      ballActive.current = false
      setBallFlying(false)
    }
  }

  drawFrame()
}, running)
```

**Что здесь главное.**

- `TIME_ZOOM = 4` ускоряет анимацию, но **соотношение скоростей сохраняется**. Если мяч в 4 раза медленнее поезда, на экране он тоже будет в 4 раза медленнее.
- Подпись над мячом показывает сумму: `trainSpeed + ballSpeed`.
- Это **не** релятивистская формула. Для малых скоростей она совпадает с классической; модель нужна, чтобы показать привычную картину, а затем сравнить её со светом.
- В уроке после этой модели объясняется, почему для света так складывать нельзя: скорость света одинакова во всех инерциальных системах.

**Где я упростил.** Мяч летит по прямой, без сопротивления воздуха и силы тяжести. Это мысленный эксперимент, а не физическая лаборатория.

### 4.18. Появление блоков при прокрутке: `IntersectionObserver`

**Задача.** Сделать аккуратные анимации появления секций, но не грузить страницу и не мешать людям, которые отключили движение.

**Идея.** `IntersectionObserver` сообщает, когда элемент попал в область видимости. После первого появления я перестаю за ним следить и добавляю класс `is-visible`. CSS делает плавный переход.

**Код.**

`src/components/Reveal.jsx`, строки 18–35:

```jsx
useEffect(() => {
  const node = ref.current
  if (!node || typeof IntersectionObserver === 'undefined') return

  const observer = new IntersectionObserver(
    (entries) => {
      entries.forEach((entry) => {
        if (!entry.isIntersecting) return
        setVisible(true)
        observer.unobserve(entry.target)
      })
    },
    { threshold: 0.12, rootMargin: '0px 0px -48px 0px' },
  )

  observer.observe(node)
  return () => observer.disconnect()
}, [])
```

**Что здесь главное.**

- `threshold: 0.12` — блок должен показаться хотя бы на 12%, чтобы сработала анимация.
- `rootMargin: '0px 0px -48px 0px'` — небольшой отступ снизу, чтобы анимация начиналась чуть раньше, чем блок полностью доедет.
- `unobserve` после срабатывания экономит ресурсы: элемент больше не проверяется.
- Если `IntersectionObserver` не поддерживается, блок сразу видим — сайт не ломается.
- В `src/index.css`, строки 231–248, есть `@media (prefers-reduced-motion: reduce)`: анимации отключаются, блоки показываются сразу. Это важно для доступности.

**Почему не библиотека анимаций.** Для появления секций хватает 20 строк и CSS. Библиотека добавила бы вес и зависимость без пользы для проекта.

### 4.19. Дизайн-система: почему сайт не выглядит как «ещё один ИИ-сайт»

**Задача.** Сделать спокойный школьный сайт, которому доверяет учитель: без неоновых градиентов, стоковых роботов и «магии ИИ».

**Решения.**

- **Светлая «бумажная» тема** по умолчанию: тёплый фон `#f7f5ef`, тёмный графит, зелёный акцент. Тёмная тема — для тех, кому удобнее.
- **Серифные заголовки** (`--font-display`) и системный гротеск в тексте. Это ближе к учебнику и журналу, чем к SaaS-лендингу.
- **Тонкие линии и минимум теней.** Границы сделаны через `--color-border`, а не через тяжёлые рамки.
- **Семантические CSS-переменные.** Компоненты не хардкодят цвета; при смене темы меняются только значения переменных.
- **Линейные SVG-иллюстрации** в `src/components/Illustrations.jsx`: книга, орбита, карточка с галочкой. Без растровых стоковых картинок.
- **Учительская — заметная, но не агрессивная.** В шапке есть отдельная кнопка «Для учителя», на главной — блок с двумя сценариями.
- **Доступность.** Skip-link, `:focus-visible`, `aria-label` у переключателя темы и меню, `role="progressbar"` у прогресса, `prefers-reduced-motion`.
- **Адаптивность.** Сетки на `minmax`, мобильное меню, таблицы и листы A4 прокручиваются по горизонтали на узком экране.

**Что здесь главное.** Дизайн — не «украшение», а часть доверия. Учитель должен понимать, что сайт не пытается продать ему подписку. Поэтому: никаких всплывающих окон, никакой регистрации, никаких обещаний «ИИ выучит всё за вас».

### 4.20. Деплой: GitHub Actions, относительные пути и домен

**Задача.** Сайт должен открываться и на старом адресе GitHub Pages, и на своём домене `alma-edu.ru`, без ручной сборки под каждый вариант.

**Идея.** Vite собирает статические файлы. Если указать `--base=./`, все ссылки на ассеты становятся относительными (`./assets/...`). Тогда один и тот же `dist` работает и в подпапке `/alma-site/`, и в корне домена.

**Код.**

`.github/workflows/deploy.yml`, строки 29–45:

```yaml
- name: Install dependencies
  run: npm ci

- name: Build
  run: |
    npm run build -- --base=./
    cp dist/index.html dist/404.html

- name: Setup Pages
  uses: actions/configure-pages@v5
  with:
    enablement: true

- name: Upload artifact
  uses: actions/upload-pages-artifact@v3
  with:
    path: dist
```

**Что здесь главное.**

- Workflow запускается на каждый push в `main`.
- `npm ci` ставит зависимости строго по `package-lock.json` — сборка воспроизводима.
- `cp dist/index.html dist/404.html` — запасной fallback для GitHub Pages: если пользователь откроет неизвестный путь, GitHub отдаст `404.html`, а там уже работает React Router.
- `public/CNAME` содержит `alma-edu.ru`. При сборке файл попадает в корень `dist`, и GitHub Pages понимает, какой домен использовать.
- DNS: четыре A-записи домена указывают на IP GitHub Pages (`185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`), `www` — CNAME на `qqquies.github.io`.
- HTTPS включается в настройках GitHub Pages после того, как GitHub подтвердит домен и выпустит сертификат. Если кнопка `Enforce HTTPS` временно недоступна, это обычно означает, что DNS ещё не подтвердился; нужно подождать и повторить.

**Почему не Timeweb-хостинг.** Домен куплен в Timeweb, но сам сайт статический. Ему не нужен PHP, база данных и оплата виртуального хостинга. GitHub Pages бесплатно отдаёт статику, а Timeweb остаётся регистратором домена и DNS. ИИ-часть при этом живёт отдельно, на бесплатных Cloudflare Pages Functions, поэтому покупать PHP-хостинг не пришлось.

**Что здесь главное.** Домен и хостинг — разные услуги. Домен — это адрес; хостинг — это место, где лежат файлы. Можно купить домен в Timeweb и держать сайт на GitHub Pages. Именно так и сделано.

На момент подготовки документа:

- `npm run lint` — **без ошибок**.

### 6.2. Ручные сценарии

Проверялись вручную:

- открытие главной, модулей, урока, учительской, презентаций, 404;
- обновление страницы на вложенном маршруте (HashRouter);
- прохождение урока и отметка «Пройден»;
- скрытие текста урока после старта квиза;
- разблокировка итоговой работы после всех уроков;
- пересдача квиза и итоговой работы;
- переключение светлой и тёмной темы, сохранение после перезагрузки;
- сборка работы из банка, два варианта, ключ, пояснения, бланк;
- предпросмотр A4 и печать в PDF;
- экспорт `.pptx` в демо-режиме;
- мобильное меню и адаптивность.

### 6.3. Чего пока нет

- **Автотесты есть только у серверной части ИИ.** 12 тестов в `cloudflare/worker.test.mjs` проверяют CORS, валидацию, разбор ответа, сортировку и ошибки. Интерфейс, `buildTest`, `rng` и шкала пока проверяются вручную, линтером и сборкой.
- **Нет CI-проверки линтера.** Workflow собирает сайт, но не запускает `npm run lint`. Можно добавить отдельным шагом.
- **Нет серверного журнала оценок.** Оценки не сохраняются; это самопроверка.
- **Нет античита.** Материал скрывается CSS, а не сервером.
- **ИИ работает, но остаётся черновиком.** Модель может ошибиться в арифметике или факте; учитель обязан проверить каждое задание и каждый слайд. Это ограничение модели, а не скрытая ошибка.
- **`npm audit` предупреждает о двух high-уязвимостях** в транзитивной зависимости `image-size` внутри `pptxgenjs`. Картинки в презентации не вставляются, поэтому практического пути эксплуатации в текущем сценарии нет, но зависимость стоит обновить, когда выйдет исправленная версия. `npm audit fix --force` откатывает `pptxgenjs` на 4.0.0 — это breaking change, поэтому автоматически делать не стали.

## 9. Вероятные вопросы жюри и ответы

### 1. Почему проект называется Alma?

Alma Mater — традиционное обозначение места получения образования, «кормящая мать». Название короткое, спокойное и не привязано только к физике: проект задуман как помощник по разным предметам.

### 2. Почему React, а не обычный HTML?

В проекте много повторяющихся блоков: уроки, карточки, квизы, формы. React позволяет описывать их компонентами и не дублировать разметку. При этом нет тяжёлой UI-библиотеки: стили написаны вручную, чтобы сайт выглядел как школьный проект, а не как типовой конструктор.

### 3. Почему HashRouter, а не BrowserRouter?

GitHub Pages — статический хостинг. Он не умеет перенаправлять все пути на `index.html`. С `BrowserRouter` обновление страницы на `/modules/relativity` дало бы 404. Хэш `#/modules/relativity` не отправляется на сервер, поэтому работает всегда. Зато бесплатно и надёжно.

### 4. Где хранится прогресс? Что будет, если ученик очистит браузер?

В `localStorage`, ключ `alma-progress`. Если очистить данные сайта, прогресс начнётся заново. Это ограничение выбранной модели без аккаунтов. Для школьного проекта это плюс: я не собираю персональные данные. Если понадобится синхронизация, придётся добавить вход и базу данных.

### 5. Как вы гарантируете, что задания не повторяются?

В сборщике есть `Set` с текстами уже выбранных заданий. Кандидат принимается, только если его текста там нет. На одну позицию даётся до 40 попыток, на запасной добор — до 500. Если тема слишком узкая, интерфейс предлагает «Сборную работу по всем темам».

### 6. Откуда берутся неверные ответы?

Из типичных ошибок: умножил вместо деления, забыл перевести единицы, взял среднее арифметическое вместо средней скорости. В `numericAnswer` правильный ответ считается формулой, а дистракторы — это `value * 2`, `value / 2`, `value * 3`, `value / 4` и специальные значения для конкретной задачи. Все они проверяются на уникальность и положительность.

### 7. Как считается оценка?

У ученика — по доле правильных ответов: 90% — «5», 75% — «4», 60% — «3», ниже — «2». У учительской работы — по сумме баллов: задания разного уровня весят 1, 2 и 3 балла, пороги 85%, 70% и 50% от максимума. Это разные шкалы, потому что в первом случае все вопросы равны, а во втором — нет.

### 8. Как работает ИИ и почему ему можно доверять?

ИИ подключён через Cloudflare Pages Functions. Браузер отправляет предмет, класс, тему и количество заданий на `https://alma-ai-73x.pages.dev/api/generate`. Сервер добавляет методический промпт, вызывает Workers AI и проверяет ответ: ровно четыре разных варианта, `correctIndex` от 0 до 3, допустимый уровень. Только после этого черновик попадает на экран «Проверка черновика». Учитель может исправить формулировку, поменять верный ответ или удалить задание. Доверять модели полностью нельзя — и не нужно: она готовит черновик, решение остаётся человеку.

### 9. Есть ли ключ модели и где он хранится?

Ключа нет. Используется Workers AI: модель запускается на стороне Cloudflare, поэтому в проекте нет ни API-ключа, ни файла с секретом. Это одновременно безопаснее и проще: нечего случайно закоммитить. Доступ к генератору всё равно закрыт: CORS пускает только адреса Alma, тело запроса ограничено 20 КБ, с одного IP — не больше 20 запросов в час, а модель прерывается через 65 секунд. Если позже понадобится OpenRouter, ключ будет храниться как секрет Cloudflare и в браузер не попадёт.

### 10. ИИ может ошибиться. Что тогда?

Да, может. Поэтому он не печатает работу сам: учитель видит каждое задание, может исправить формулировку, поменять верный ответ или удалить задание. Модель обязана помечать сомнительные ответы `check: "mismatch"`, а интерфейс показывает «проверить ответ». Оценки ИИ не ставит.

### 11. Скрытие материала — это античит?

Нет. Это CSS-скрытие, оно убирает соблазн подсмотреть, но не защищает от DevTools. Для настоящего античита нужен сервер, который выдаёт вопросы и принимает ответы. Я честно указываю это в ограничениях.

### 12. Почему не Timeweb-хостинг, если домен там?

Домен и хостинг — разные услуги. Домен куплен в Timeweb, но сайт статический, ему не нужен PHP и база. GitHub Pages бесплатно отдаёт статику, а Timeweb остаётся регистратором и DNS. ИИ-часть живёт на бесплатном Cloudflare Pages, поэтому отдельный PHP-хостинг не понадобился. Это минимальная достаточная конфигурация.

### 13. Что будет, если на сайт зайдёт много людей?

Статика GitHub Pages масштабируется сама: это не мой сервер. Узкое место — только ИИ-генератор: бесплатный дневной запас Workers AI и лимит 20 запросов в час с одного IP. Банк заданий считается на устройстве пользователя, поэтому нагрузка распределяется между браузерами.

### 14. Как вы проверяли факты в уроках?

Тексты уроков проверялись автором, а карточки учёных содержат ссылки на источники. В спорных местах я старался не выдумывать даты и формулировки. Если жюри найдёт неточность, это можно исправить в одном файле урока — архитектура позволяет.

### 15. Что дальше?

Три направления: автотесты для интерфейса и генератора заданий, расширение банка и новые предметы, синхронизация прогресса. Ещё можно добавить аккаунты, но это уже требует защиты персональных данных.

## 11. Команды для запуска и проверки

```bash
npm install          # установить зависимости
npm run dev          # локальный сервер → http://localhost:5173
npm run lint         # проверка кода
npm run build        # production-сборка в dist/
npm run preview      # посмотреть production-сборку
npm run test:worker  # 12 тестов серверной части ИИ
npm run deploy:pages # обновить ИИ на Cloudflare Pages
```

Локальная демонстрация ИИ без сети и без модели:

```bash
# .env.local в корне проекта
VITE_AI_MOCK=1
```

Затем `npm run dev` и открыть `#/teacher` или `#/teacher/presentation`. В обычной сборке без этой переменной демо-данные не попадают в бандл.

Для реального ИИ в production уже прописан адрес:

```bash
# .env.production
VITE_AI_ENDPOINT=https://alma-ai-73x.pages.dev/api/generate
```

Локально можно создать `.env.local` с тем же адресом. Серверная часть описана в `cloudflare/README.md`; вариант на PHP остаётся в `server/README.md` как запасной.
